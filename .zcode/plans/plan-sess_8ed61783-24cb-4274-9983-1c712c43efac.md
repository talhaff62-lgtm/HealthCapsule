# Plan: Registration Pages for Doctors & Healthcare Centers + Admin Verification/Tier Tags + Public Facility Detail Page

## Overview
Add public self-registration for doctors and healthcare/diagnostic centers, extend the existing admin dashboard so admins can verify those registrations and assign `ListingTier` tags, and add a public facility detail page at `/healthcares/[slug]`. The Prisma schema already supports all of this, so no migration is needed.

## Decisions (based on your answers)
- **Single registration page with tabs**: `/register` with "Doctor" and "Healthcare Center" tabs. URL query `?type=facility` pre-selects the facility tab for direct links.
- **Auto-login after registration**: Client signs the user in with the same credentials, then redirects to `/portal` so the existing role-based redirector sends them to the right dashboard.
- **Extend existing admin page**: `/portal/admin` gets a "Doctors / Facilities" switcher and reuses the same status filters; facilities render a new `AdminFacilityRow`.
- **Minimal initial fields**: only the data needed to create a pending record; full profile details are added later in the doctor/facility portal.
- **Public facility detail page**: `/healthcares/[slug]` shows verified facility info, contact details, and a link back to the listing.
- **Email/OTP verification**: out of scope for now, as requested.

## Files to Create

### 1. `src/lib/slug.ts`
Shared slug helper:
- `slugify(name)` → lower-case, hyphenated, ASCII-safe slug.
- `generateUniqueSlug(base, exists)` → appends a short counter/suffix until the slug is unique.

### 2. `src/lib/facilities.ts`
Facility search helpers mirroring `lib/doctors.ts`:
- `searchFacilities({ type, area, q })` → typed `FacilityListItem[]`.
- `isFeaturedFacility(tier)` helper.
- Used by `/healthcares/page.tsx` and `/healthcares/[slug]/page.tsx`.

### 3. `src/app/register/page.tsx` (Server Component)
- Reads `searchParams.type` to determine the default tab.
- Fetches `specialties` and `areas` for dropdowns.
- Renders `RegisterForm` with those options.
- Page metadata: "Register — HealthCapsule".

### 4. `src/app/register/RegisterForm.tsx` (Client Component)
- Tab switcher: Doctor / Healthcare Center.
- Form fields:
  - **Common**: phone (`01XXXXXXXXX`), password (min 6).
  - **Doctor**: full name, BMDC registration number, primary specialty select.
  - **Facility**: facility name, type select (Hospital / Diagnostic Center / Clinic), area select, address.
- Validates client-side, shows loading + inline error/success banners.
- On server success: calls `signIn("credentials", { phone, password, redirect: false })`, then `router.push("/portal")` + `router.refresh()`.

### 5. `src/app/register/actions.ts` (Server Actions)
Two actions, both returning `{ ok: true } | { ok: false; error: string }`:
- `registerDoctor({ phone, password, name, bmdcRegNo, specialtyId })`
  - Validates phone/password/name/BMDC.
  - Hashes password with `bcryptjs.hash(password, 10)`.
  - Generates unique slug from name.
  - Creates `User(role: DOCTOR)` + `Doctor(userId, verificationStatus: PENDING, listingTier: FREE, ...)` + `DoctorSpecialty`.
  - Catches Prisma `P2002` for duplicate phone/BMDC and returns friendly messages.
- `registerFacility({ phone, password, name, type, areaId, address })`
  - Same validation/hashing pattern.
  - Creates `User(role: FACILITY_ADMIN)` + `Facility(adminId, verificationStatus: PENDING, listingTier: FREE, ...) `.
  - Catches duplicate phone.

### 6. `src/components/admin-portal/AdminFacilityRow.tsx` (Client Component)
Mirrors `AdminDoctorRow`:
- Displays facility name, type label, verification status badge, listing tier badge, area/address, admin phone, submission date.
- Link to public facility detail page `/healthcares/${slug}`.
- Verification status pill buttons (`PENDING / VERIFIED / REJECTED`).
- Listing tier `<select>` (FREE / VERIFIED / FEATURED / PREMIUM).
- Uses `setFacilityVerificationStatus` and `setFacilityListingTier` server actions.

### 7. `src/app/healthcares/[slug]/page.tsx` (Server Component)
- Looks up verified facility by slug, `notFound()` if missing/inactive.
- Shows facility name, type badge, address, phone, email, website, description, established year, bed/ICU/NICU/emergency/ambulance badges.
- Link back to `/healthcares`.

## Files to Modify

### 8. `src/app/portal/admin/page.tsx`
- Add `type` query param (`"doctor" | "facility"`, default `"doctor").
- Add type switcher tabs (Doctors / Facilities) alongside the existing status tabs.
- When `type === "facility"`, query `prisma.facility.findMany` with status filter, include `area` and `admin: { select: { phone: true } }`.
- Count facilities and render `AdminFacilityRow`.
- Keep existing doctor behavior as default, so old `/portal/admin` links still work.
- Update subtitle/page copy to mention facilities.

### 9. `src/app/portal/admin/actions.ts`
- Add `setFacilityVerificationStatus(facilityId, status)` — updates `Facility.verificationStatus`, sets `verifiedAt` when status is `VERIFIED`.
- Add `setFacilityListingTier(facilityId, tier)` — updates `Facility.listingTier`.
- Both guard with `requireRole(UserRole.ADMIN)`, `revalidatePath("/healthcares")` and `revalidatePath("/portal/admin")`.

### 10. `src/app/portal/page.tsx`
- Extend role redirect to handle `FACILITY_ADMIN` → `/portal/facility`.
- Keep fallback for unknown roles (send to `/login`).

### 11. `src/components/home/CtaBanner.tsx`
- Change "Doctor Registration" link from `/portal/doctor` to `/register?type=doctor`.
- Add a second button "Healthcare Registration" linking to `/register?type=facility`.

### 12. `src/components/admin-portal/AdminDoctorRow.tsx` (small polish)
- Render the existing `TierBadge` component next to the doctor name so admins see the current tier visually, not only in the dropdown.

### 13. `src/app/healthcares/page.tsx`
- Replace the placeholder `#` link with `/healthcares/${facility.slug}`.
- Optionally use `searchFacilities` from `lib/facilities.ts` for consistency.

- `featuredUntil` date picker for time-bound FEATURED/PREMIUM boosts (the column exists; can be added later).
